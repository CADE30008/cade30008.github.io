# The diagnostic in Blackboard Ultra: what to try, and what to record

!!! note "On hold, 21 September 2026"
    **Decision: the diagnostic stays in Numbas for now.** Ultra cannot give
    item-by-item feedback inside a quiz the way the question set needs, and
    that mechanism is the whole point of it: every option carries its own
    diagnosis, and a student who guessed right still learns why. A version
    without that is a score, not a diagnostic.

    Nothing here is wasted. The generator still builds from the same YAML, so
    if Ultra's feedback handling changes, or if a future question set does not
    depend on per-option feedback, this is ready to test. The probe package
    below is still the right first step when that day comes.

Generated by `npm run bb` from `diagnostics/prerequisites.yaml`, the same source
as the Numbas exam. Nothing here is edited by hand.

| File | What it is | Where it goes |
|---|---|---|
| `PROBE.zip` | Ten small questions, each isolating one thing we cannot settle from the documentation. | Content → Details & Actions → **Manage banks** → + → Import from QTI 2.1 package |
| `prerequisites-qti.zip` | All eleven questions, with per-option feedback and the worked routes. | Same place |
| `prerequisites-upload.txt` | All eleven questions, no feedback and no figures. | Inside a test: + → **Upload questions from file** |

## What Ultra can do, from the documentation

- **Per-answer feedback on multiple choice.** Each option carries its own text,
  and a student sees only the one they picked. That is the diagnostic mechanism
  the whole question set is built around, and Ultra has it.
- **Numeric answers with a tolerance**, as Calculated Numeric questions.
- **Multiple attempts**, and feedback shows on every attempt including ungraded
  ones.
- **A formative flag**, which labels the assessment to students and can be
  excluded from the grade calculation.
- **LaTeX**, rendered by MathJax, in any rich-text field. This is the part that
  is not guaranteed: MathJax rendering arrived as a release feature rather than
  something always on, so whether `\( ... \)` renders here is a question about
  this installation. Probe 1 asks it.

## What Ultra cannot do

- **Nothing is shown during an attempt.** Every Assessment Results setting
  releases after submission: submitted answers, question scores, correct
  answers and automated feedback alike. There is no equivalent of the "Show
  steps" button, which in Numbas puts the full working in front of a student
  while the question is still on screen and costs them nothing.

  The nearest substitute is unlimited attempts with results released
  immediately: answer, submit, read the working, go round again. That turns a
  read-during into a read-between, and it is a real difference for a student
  who wants the method before committing to an answer.

- **Question-level and per-answer feedback are mutually exclusive.** A question
  cannot have both the diagnosis of the chosen option and a shared worked
  route. The generated package appends the worked route to every option
  instead, so the file repeats itself four times over and the student sees it
  once.

- **QTI import is narrow.** Anthology lists Multiple Choice, True/False, Fill
  in the Blank and Essay as supported, and says questions using "the optional
  QTI response processing" are skipped. The four numeric questions are written
  out anyway, because a skipped question costs nothing and probe 10 tells us
  whether the documentation is complete.

- **The tab-delimited upload carries no feedback and, per the documentation, no
  images.** It takes NUM questions, which QTI may not, so between the two
  routes every question type is covered but no single route covers everything.

- **QTI packages import into a question bank, not into a test.** Build the test
  afterwards and add the bank's questions to it.

## The protocol

Do these in order. Each one stops being worth doing if the one before it
failed.

1. **Import `PROBE.zip`** into a question bank in a sandbox course, not the
   unit. Put all ten into a test, set Assessment Results to release everything
   after submission, and sit it in student preview. Each question says on
   screen what to look for and each option's feedback says what it proves.

   Record, against each probe: LaTeX inline, LaTeX display, MathML, figure as a
   packaged file, figure as a data URI, per-option feedback written inline,
   per-option feedback written as modal feedback, rich feedback, figure inside
   feedback, numeric question imported at all.

2. **Build one question by hand** in Ultra: multiple choice, four options,
   per-answer feedback on each, one equation through the WIRIS editor. Export
   that bank to QTI 2.1 and read the XML. Blackboard's own export is the only
   definitive statement of what its import expects, and it settles in one look
   what probes 6 and 7 can only narrow down.

3. **If probes 6 or 7 passed**, import `prerequisites-qti.zip`. It is generated
   with `--feedback=both`, so if Ultra honours both forms every option's
   feedback appears twice. Rerun `npm run bb -- --feedback=inline` (or `modal`)
   once you know which.

4. **If they failed**, `prerequisites-upload.txt` still puts all eleven
   questions into a test in one go, and the feedback goes in by hand
   afterwards: seven multiple-choice questions with twenty-eight options between
   them, four numeric ones, and eleven worked routes.

5. **Either way**, the three questions with figures need checking by eye. Two
   of them are unanswerable without the figure.

## What the answer depends on

If LaTeX renders and per-option feedback survives an import, Ultra can carry
this diagnostic, at the cost of the worked route moving from during the attempt
to between attempts, and of the numeric questions either becoming multiple
choice or losing their per-answer feedback.

If LaTeX does not render, every equation goes through the WIRIS editor by hand.
There are 11 questions, 28 options and 11 worked routes, nearly all with
several equations in them. That is the point at which Numbas is the cheaper
answer, and the one the question set was written for.
